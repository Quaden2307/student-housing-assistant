# Decisions

One entry per non-trivial decision: date, decision, why. Newest at the bottom.
Changes to the contracts (HANDOFF sections 2, 3 and 5) need Caden's sign-off and are logged here too.

| Date | Decision | Why |
|---|---|---|
| 2026-10-04 | Pin Python 3.11 in `.python-version` (`requires-python >= 3.11`). | 3.11 is the floor HANDOFF names and the safest target for the Phase 2 stack (LightGBM, SHAP, sentence-transformers). 3.13 is also installed via uv if we want to move later. |
| 2026-10-04 | Project name `student-housing-assistant`, import package `housing` under `src/`, built with `uv_build` (`module-name = "housing"`). | Matches the layout in HANDOFF section 6 (`src/housing/...`) while keeping the repo name for the distribution. |
| 2026-10-04 | ruff enforces pydocstyle (Google convention) on `src/` and `scripts/`; tests are exempt from docstring rules. | Makes the "docstrings on public functions" convention a lint failure instead of a code-review nag. |
| 2026-10-04 | Add dependencies only when code that uses them lands (today: `pyyaml`; dev: `pytest`, `ruff`). | Keeps the lockfile honest about what the pipeline needs; scraping and ML libraries arrive with tasks 4 to 5 and Phase 2. |
| 2026-10-04 | All file locations go through `housing.paths` (repo root derived from the package location; `HOUSING_DATA_DIR` and `HOUSING_DB_PATH` env overrides). | Notebooks, scripts and tests run from different working directories; one module settles where `data/`, the DB and the schema live, and tests can redirect to a temp dir. |
| 2026-10-04 | `src/housing/db/schema.sql` is the section 5 DDL verbatim with `IF NOT EXISTS`; no indexes yet. | Keep the contract file identical to HANDOFF. Indexes get added, and logged here, when a query needs them. |
| 2026-10-04 | Every connection from `housing.db.connect` turns on `PRAGMA foreign_keys` and WAL journaling. | SQLite ignores `REFERENCES` unless foreign keys are enabled per connection. WAL lets a notebook read while the sweep writes. |
| 2026-10-04 | Schema version lives in SQLite's `PRAGMA user_version` (now 1); no migrations table. | Avoids creating a table outside the section 5 contract. Future changes bump `SCHEMA_VERSION` and add guarded `ALTER` steps in `migrate.py`. |
| 2026-10-04 | TEXT timestamps are ISO 8601 UTC (`2026-10-05T14:03:00Z`); `posted_at` is `YYYY-MM-DD`; booleans in `units` are 0, 1 or NULL. | Section 5 declares TEXT but not a format. Fixing it before the first sweep keeps rows sortable and comparable across sources. |
| 2026-10-14 | Start collecting from Kijiji now with daily index sweeps (about 50 requests a run). Kijiji's Terms clause on automated access is recorded in `docs/sources.md` section 1. | Caden asked to start getting data; HANDOFF section 4 names Kijiji as the primary source; the footprint is one worker, one request every 2 to 3 seconds. |
| 2026-10-14 | The sweep reads the index pages' embedded `__NEXT_DATA__` JSON, writes one `snapshots` row per listing per run with the card price, and leaves detail pages to a separate step. | Apartments cards already carry the section 3 fields; this is the cheapest path to a dataset and the history clock starts today. |
| 2026-10-14 | `listings.posted_at` is Kijiji's `activationDate` (first posting) as `YYYY-MM-DD`; `sortingDate` (bumps) is ignored. | Bumps reset the listing order, not when the ad first appeared. |
| 2026-10-14 | Titles are stripped of emails and phone numbers on write (`housing.parse.pii`); the truncated card description is not stored. `listings.description` is filled only from detail pages, after stripping. | A 200-character snippet would be mistaken for the full text downstream. Names are not detected yet. |
| 2026-10-14 | `housing.scrape.fetch.Fetcher`: robots.txt per host with a wildcard-aware matcher, 2 to 3 s between requests, three attempts on connection errors and 5xx, hard stop on 403, 429 or a challenge page, raw bodies gzipped under `data/raw/<source>/<date>/` and served from that cache on a repeat call the same day. | HANDOFF's blocking playbook. `urllib.robotparser` ignores `*` wildcards and would allow URLs Kijiji forbids. |
| 2026-10-14 | Promoted (`TOP_AD`) cards repeat across index pages; a listing gets one snapshot per run. | Avoids double-counting sightings. |
| 2026-10-14 | `uv_build` upper bound widened to `<0.14.0`. | Mark's uv 0.13.1 warned on the old bound; builds are unchanged. |
| 2026-10-14 | DB schema version 2 adds one auxiliary table, `listing_attributes(listing_id, name, value)`, outside the five contract tables. Every raw Kijiji attribute, plus our own flags (`category`, `poster_hash`, `image_count`, `text_*` extraction flags), lives there. | Features can be added later without widening `units`; the contract tables stay verbatim. Flagged for Caden's sign-off as a section 5 addition. |
| 2026-10-14 | Poster account ids are stored only as a salted SHA-256 prefix (`HOUSING_HASH_SALT` in `.env`); the poster's name and phone are never read. | Lets dedup catch reposts by the same account without storing contact info. |
| 2026-10-14 | Detail pages: full description stored with contact details stripped; card coordinates and dates are kept over the detail page's (it rounds coordinates when the pin is hidden). Rooms listings are fetched first, 300 pages per daily run by default. | Rooms have no structured fields; apartments mostly do. |
| 2026-10-14 | Unit extraction conventions: studio stored as `bedrooms = 1`; `house` from Kijiji's unit type, else by bedrooms; per-room ads under the apartments category become `unit_type = room` with the house's bedroom count; a room ad's bedrooms is the largest count in the text; `utilities_included` is heat, hydro and water all included (internet excluded); `move_in_month` only when stated; `building_type` from a known-building registry or explicit student-building wording, `house` for houses and basements, else `unknown`. Extra signals go to `listing_attributes` as `text_per_room_price`, `text_is_takeover`, `text_bathroom_private`, `text_available_now`, `text_internet_included`, `text_building_name`. | Decided while writing `housing.parse.units`; repeated in `schema/unit_schema.yaml`. |
| 2026-10-14 | A listing becomes `gone` when a complete sweep of both categories finds its `last_seen` older than 40 hours (two missed daily runs); an incomplete or blocked sweep marks nothing. | One missed sweep can be a glitch; two is a vanished ad. |
| 2026-10-14 | Daily job: `scripts/sweep.py` runs sweep, gone marking, details, extraction, features rebuild and a Discord report (`DISCORD_WEBHOOK_URL` in `.env`; prefixed ALERT on zero listings, a block or a parse failure). Scheduled on Caden's Mac via launchd at 06:30 (`scripts/install_launchd.sh`). | HANDOFF section 6; mirrors the flight-price collector that already runs on this machine. |
| 2026-10-14 | `schema/unit_schema.yaml` groups are lists of `- name:` entries, not mappings; `neighbourhood` has type `str`; `lat`/`lon` carry implied bounds; `validate` rejects NaN for floats. | PyYAML silently keeps the last duplicate mapping key, which would hide duplicate fields; the derived table has no type column and `str` matches `features.neighbourhood TEXT`; pandas represents missing floats as NaN. |
| 2026-10-14 | Test files are exempt from the line-length rule (`E501`). | Long literal strings in fixtures and SQL make tests harder to read when wrapped. |
| 2026-10-16 | Index pages are always fetched fresh (`refresh=True`); only detail pages and robots.txt use the same-day raw cache. | The Oct 14 evening run was served page 1 from a six-hour-old cache and wrote 1,852 snapshots with zero requests. A snapshot must be a real sighting. |
| 2026-10-16 | Raw pages are scrubbed before they are written to `data/raw/` (`housing.parse.pii.scrub_page`: poster name and phone nulled, titles and descriptions stripped); pages saved before this were scrubbed in place with `scripts/scrub_raw.py`. | HANDOFF section 5: never store contact info. Parsers never read those fields, so re-parsing loses nothing. This departs from storing responses verbatim; flagged for Caden. |
| 2026-10-16 | Contact stripping also covers written-out emails, spaced and spelled-out phone numbers, seven-digit numbers after a contact word, names after contact phrases and sign-offs, and the URL slug (Kijiji serves a detail page by its trailing ad id with any slug, verified live on 2026-10-16). `scripts/restrip.py` re-applies the rules to stored rows. | Review found full phone numbers and first names surviving in stored descriptions and one phone number in a URL. |
| 2026-10-16 | `HOUSING_HASH_SALT` is mandatory (`hash_id` raises without it) and `.env` is loaded by `housing.paths` on import, so every CLI uses the same salt. | A development salt made poster hashes reversible and inconsistent between entry points. |
| 2026-10-16 | The daily run never dies silently: a fetch failure exits 4, a crash exits 1, both with an ALERT posted. A sweep is incomplete, so nothing is marked gone and the report ALERTs, when the page cap is hit, fewer than 90 percent of the site's count was seen, pagination stops advancing, or a page reports zero listings. | HANDOFF section 6: a silently dead scraper is the usual way these projects die. |
| 2026-10-16 | Detail pages: a failed fetch keeps a null description and is retried after 3 days; the pass stops after 3 consecutive failures; a redirect to the search page means the ad was removed (`detail_error = removed`); the parsed page must carry the expected ad id. | Transient network errors were being recorded as permanent, which would have silently lost every rooms listing's text. |
| 2026-10-16 | Extraction rules tightened: a month range is read by its span (up to 5 months sublet, 6 to 9 an 8-month lease, longer a year) after explicit wording, and "no sublets" is ignored; an explicit text statement beats Kijiji's flags for utilities and furnishing ("not furnished" is unfurnished); `year_built_after_2018` from wording only for new build, new construction, newly built or a build year of 2019 or later; the ISO-date fallback for move-in only next to availability wording, and "may" only capitalised or with a day; the building registry matches whole street numbers with street words normalised ("1 Columbia Street West" matches, "121 Columbia St W" does not); "bedroom for rent" after a count is a whole unit; a per-room ad under apartments takes the larger of the attribute and text bedroom counts; `text_*` flags are deleted before each re-extraction. | Review of the first run found 13 sublets mislabelled from long ranges, a two-bedroom stored as a room, false registry matches, "not furnished" stored as furnished and "utilities not included" stored as included. |
| 2026-10-16 | Conventions that were in the code but not logged: bathrooms are Kijiji's value divided by 10 when above 8; walking minutes are straight-line metres over 80; whole-unit wording under the rooms category gives a bedroom-count type; `extracted_by` is `page_attrs` only when the bedroom count came from attributes. | Review asked for every applied convention to be in this log. |
| 2026-10-16 | Open for Caden's sign-off (section 3 readings): a studio stored as `bedrooms = 1` with `min: 1`; `bedrooms` treated as optional for `unit_type = room`, since only about 40 percent of room ads state the house total. | The contract says bedrooms is required and "total bedrooms in the whole unit", which reads as 0 for a studio. |
